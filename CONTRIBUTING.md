# Contributing to Threadseer support documentation

This repository accepts public documentation corrections and privacy-safe issue
reports. The Threadseer product source remains private and is not developed in
this repository.

## Issues

Use the issue forms for reproducible product problems and feature requests. Do
not submit employer or customer event logs, PBIX/PBIP files, tenant identifiers,
credentials, personal information, proprietary field names, or screenshots
containing case data. Prefer a blank report and synthetic example. A GitHub
account and sign-in are required to open an issue.

Security vulnerabilities must use
[private vulnerability reporting](https://github.com/wittenauer-software/threadseer-support/security/advisories/new),
not a public issue.

## Documentation changes

- Keep customer language concise and factual.
- Do not claim Marketplace approval, availability, purchase, certification,
  pricing, supported scale, or product capabilities without publisher-reviewed
  release evidence.
- Preserve the statement that product source is private.
- Preserve the local-only privacy boundary and distinguish Threadseer from
  Microsoft Power BI and GitHub processing.
- Update navigation, footer links, sitemap, and review dates when adding or
  materially changing a page.
- Run `python tools/validate_docs.py` before opening a pull request.

By contributing content, you represent that you have the right to provide it and
grant Wittenauer Software LLC permission to use it in Threadseer support and
documentation materials.
