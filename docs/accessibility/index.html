Accessibility

Threadseer is designed to support keyboard operation, readable focus, semantic controls, high-contrast themes, reduced motion, and responsive Power BI layouts.

Supported behavior

  • Workspace tabs and interactive controls are keyboard reachable and expose visible focus.
  • Arrow, Home, and End keys support workspace-tab navigation.
  • Tables use semantic headings, buttons, labels, and bounded pagination.
  • Process-map elements expose textual labels and keyboard focus in addition to visual styling.
  • High-contrast colors and reduced-motion preferences are respected where the Power BI host supplies them.
  • Status, stale-snapshot, loading, cancellation, error, and data-quality messages use text rather than color alone.
  • Layouts adapt across compact, standard, and focus-mode visual sizes.

Host and content boundaries

Threadseer runs inside Microsoft Power BI, so final focus order, zoom, screen-reader behavior, theme contrast, and export behavior also depend on the Power BI host, browser or WebView2, report design, and operating-system accessibility settings.

Dense process maps and wide analytical tables can require a larger visual or Power BI focus mode. Use the Cases and supporting table views when a graphical path is difficult to inspect.

Report an accessibility problem

Use the support guide and public bug form for a non-confidential reproduction. Include the Threadseer and Power BI versions, assistive technology and version, input method, viewport or zoom, expected behavior, and actual behavior.

Keep operational data private. Do not upload report files, event logs, screenshots containing case identifiers, tenant details, personal information, credentials, or proprietary field names. Use a blank report and synthetic data.

If an accessibility request requires personal, account, purchase, legal, or other non-public information, do not place it in a public issue. A verified private support contact will be published before public sale.
