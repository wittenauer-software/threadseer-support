Getting started with Threadseer

Turn an event-level Power BI table into an interactive process snapshot without sending report or process data to the publisher or publisher-controlled services.

Version scope: Threadseer 0.1.0.110 pre-submission build · Last reviewed: August 21, 2026

What Threadseer does

Threadseer is a self-contained Power BI custom visual for process discovery and investigation. It groups events into cases, orders each case by time, discovers the paths those cases follow, and keeps the resulting analysis inside the Power BI visual environment.

Threadseer does not require a backend, a Threadseer account, Python, or a separate preprocessing application. Power Query can still be useful when source data needs reshaping before it reaches the visual.

Add Threadseer to a report

  1. Open the report in a supported Power BI authoring environment.
  2. Add Threadseer to the report canvas from the Visualizations pane using the distribution made available to you.
  3. Resize the visual so the setup guidance and workspace navigation are visible.
  4. Assign the required event fields, then apply any Power BI filters that should define the initial analysis population.
No Marketplace submission has been made. Threadseer is not publicly available. Installation, purchase, and assignment instructions will be added only after a future submission, approval, and go-live are confirmed.

Prepare the event data

Each source row should represent one event. Column names do not need to match Threadseer's role names; map the columns that carry the corresponding meaning.

Required fieldPurposeExample
Case IDGroups events that belong to the same process instance.Order ID, Ticket Number
ActivityNames the step performed at each event.Approved, Shipped
TimestampOrders events within each case.Status Changed At

If milestones are stored as separate date columns, unpivot them in Power Query so each event becomes a row. Use precise timestamps when order matters. When events in one case share a timestamp, Threadseer applies a deterministic source-row tie-breaker and reports the condition in Data Quality.

Optional field mappings

Optional fieldWhat it adds
Activity CategoryCategory labels and colors for activities on the process map.
End TimestampProcessing-time and queue-wait evidence. Without it, Threadseer does not label start-to-start time as either bottleneck type.
Event / Row IDPreserves an individual source-row identity for Power BI interactions when one is available. It does not change process calculations.
ResourceResource context for investigation; it is not presented as utilization or capacity proof.
OutcomeOutcome-rate comparisons in both editions.
Value or CostValue and cost summaries in both editions.
Additional DimensionsBounded cohort context from up to three mapped dimensions in both editions.

Analyze the current selection

  1. Confirm the required fields are mapped and review any data-quality guidance.
  2. Apply Power BI report, page, or visual filters that should define the source population.
  3. Select Analyze this selection.
  4. Wait for the complete selection to load and the analysis to finish. Threadseer never mines an incomplete loaded prefix.

Analysis is deliberate. Power BI updates, resizing, formatting changes, and navigation between Threadseer views do not silently start mining.

Filters, stale snapshots, and Reanalyze

Power BI filters define the proposed input population before analysis. After a snapshot exists, changing mapped fields or filters marks that snapshot stale but leaves the prior results visible for comparison and continuity.

Review the stale notice, then select Analyze new selection to replace the snapshot deliberately. Internal selections within Threadseer coordinate a contributing-case cohort across the workspace without rebuilding the source snapshot.

Read the workspace

Process Map

Shows activities and observed paths. Edge styling distinguishes ordinary flow, bottleneck evidence, rework returns, shortcuts, and self-loops without turning those signals into causal claims.

Variants

Ranks the distinct ordered activity sequences followed by cases and shows their volume, coverage, timing, and available outcome or value context.

Compare

Places two exact observed variants side by side. Differences are descriptive associations from the current snapshot, not causal findings.

Conformance

Lets you mark observed paths as Accepted and choose one accepted path as Primary. A unified route map emphasizes the Primary path in blue, accepted-only flow in green, and separately labelled shortcut, repetition, unexpected-path, and deviation evidence. Activity cards show cases, median activity time when End Timestamp is usable, and relative case volume. Use the visible zoom, zoom-out, and Fit controls, the mouse wheel, pointer drag, or keyboard movement to inspect the map. A case conforms only when its full activity sequence exactly matches an Accepted path; Primary changes emphasis, not scoring. An Accepted path retained from another filter context remains manageable as a zero-case row and is not drawn until the current snapshot observes it. Deviation details remain traceable to contributing cases and Driver Analysis.

Drivers

Investigates where queue wait, processing time, or rework is concentrated across supplied dimensions and observed process context. Findings are transparent associations for investigation, not causal proof.

Bottlenecks

Summarizes snapshot-relative processing and queue evidence. Valid End Timestamp observations are required for those duration categories.

Rework

Shows repeated activities, return loops, their frequency, and the cases that contribute to them.

Improve

Explores workflow regularity, supplied resource and handoff evidence, and observed shortcuts. It does not make automation, staffing, capacity, compliance, or return-on-investment recommendations.

Cases

Traces results back to matching cases and a selected case timeline. Use search or another view to narrow large cohorts.

Data Quality

Explains excluded, normalized, and retained input conditions so corrections are visible rather than silently changing process meaning.

Performance guidance

  • Start with a representative filtered population, especially when activity, variant, dimension, or case cardinality is high.
  • Community accepts up to 25,000 input events per explicit analysis.
  • Professional has a measured 100,000-event baseline; larger Adaptive Scale attempts depend on local Power BI, WebView2, memory, device, and data-shape resources.
  • If loading or analysis stops with resource guidance, narrow the Power BI filters and Analyze again.
  • Capacity is not a universal latency or memory guarantee. See Plans & Licensing and product limits.
Privacy boundary. Threadseer declares no external network privileges and does not transmit customer event data, field names, report names, case identifiers, or process metrics to the publisher.
